## 一、总体结论

架构方向是对的——Hono 中间件链、D1 权威存储、原子扣币、纯函数抽卡引擎、CHECK 兜底，这几项都做得比同类小项目扎实，**没有发现 SQL 注入、IDOR、存储型 XSS 这类结构性安全缺陷**。

但存在 **4 个 critical 问题**，其中 2 个会让部署直接失败，2 个会直接造成虚拟货币资损。它们的共同点是**恰好都落在零测试覆盖区**。

| 严重度 | 条数 | 说明 |
|---|---|---|
| critical | 4（去重后） | 上线即坏 / 资损 |
| high | 14（去重后） | 逻辑错误、安全漏洞、门禁失效 |

## 二、Critical（4 项）

### C1. `npm run deploy` 会部署出一个没有后端的空站

- `package.json:12` → `"deploy": "npm run build && wrangler deploy"`（Workers 语义）
- `wrangler.jsonc:8-10` → 只有 `assets.directory`，**既无 `main` 也无 `pages_build_output_dir`**
- 三个子代理独立复现；`wrangler deploy --dry-run` 产物仅 313 字节的 `no-op-worker.js`（对所有请求返回 404）

后端完全依赖 Pages Functions 的 `functions/` 约定，而 `wrangler deploy` 根本不会打包它。**上线后 `/api/*` 与 SSR 全部 404，约 2000 行后端一行未上线。**

设计文档 `docs/superpowers/specs/2026-04-28-workers-to-pages-migration-design.md:122` 原本就写对了 `wrangler pages deploy ./build/client`。

**修复**：`wrangler.jsonc` 改用 `"pages_build_output_dir": "build/client"`；`deploy` 脚本改 `wrangler pages deploy ./build/client`；`preview` 统一语义；部署后实测 `/api/health` 与首页 SSR 再切生产。

### C2. `.dev.vars`（含 admin 口令与 GITHUB_TOKEN）已在 git 历史中

```
$ git ls-files --error-unmatch .dev.vars   → .dev.vars   （已跟踪）
$ git log --diff-filter=A -- .dev.vars      → 25ab05f
$ (Get-Content .dev.vars) 键名 → admin, GITHUB_TOKEN, GITHUB_OWNER, GITHUB_REPO, R2_DOMAIN
```

`AGENTS.md:19` 与 `CLAUDE.md:92` 都写着它"gitignored"——**`.gitignore` 对已跟踪文件无效**，保护机制已破。当前值是占位符，但任何人按文档指引填入真实口令后 `git add` 就会直接入库。`admin` 是全站最高权限（改任意用户金币 / 删号 / 改公告）。

**修复**：立即轮换 `admin` 与 token；`git rm --cached .dev.vars`；用 `git filter-repo` 清历史；补 `.dev.vars.example` 只写键名；修正 AGENTS.md/CLAUDE.md 表述。

### C3. 骰子每局被扣两次投注（重构遗留）

```js
// src/services/gacha-service.js:596
if (!(await this.deductCoins(currentUser.id, bet))) ...   // coins -= bet
// :608-611
const netChange = reward - bet;
await this.env.DB.prepare('UPDATE users SET coins = coins + ? ...').bind(netChange, ...)
```

**净效果 = `coins - 2×bet + reward`**。36 种点数穷举（PAYOUT=2，bet=100）：

| 点数 | 种数 | reward | 玩家净损益 | UI 文案 |
|---|---|---|---|---|
| 非对子 sum≥10 | 4 | 100 | **−100** | 下次好运 |
| (5,5) (6,6) | 2 | 200 | 0 | 恭喜中奖 |
| 其余对子 | 4 | 200 | 0 | 恭喜中奖 |
| sum=7 | 6 | 400 | +200 | 恭喜中奖 |
| 其余 | 20 | 0 | **−200** | 下次好运 |

**单局期望 = 投注额的 −88.9%。** 根因是 `a750809` 引入原子扣币时，`playDice` 没跟着改——旧的 `netChange = reward - bet` 补偿语句被留了下来。

`games.jsx:210-221` 仍按 `reward - cost` 展示盈亏，所以 5/36 的"恭喜中奖"实际是打平。

**⚠️ 关键：修掉重复扣款后必须同时重调赔率。** 赔付表本身是 40/36 = **+11.11% 的玩家优势**，只修扣款会立刻把"玩家被坑"变成"无限刷币"。两处必须一起改（建议按目标 house edge 反解系数，并把倍数抽到 `business.js:86` 供前后端共用）。

### C4. 抽卡 → 分解构成无限刷币闭环（+39% ROI）

用生产 `draw-engine.js` 跑 20 万次实测（**注意：软保底把实际产出率大幅抬高**，我最初手算基础概率得出 −10%，实测推翻）：

```
实际稀有度分布：N 40.41% / R 34.24% / SR 14.73% / SSR 8.38% / UR 2.23%
每抽成本 100（十连 90）
回本收入 139.15/抽 = POINTS 53.4 + DECOMPOSE 85.7
净收益 +39.15%／抽，十连每轮净赚约 390 金币
```

无上限、无冷却、且抽卡/分解路由**完全没有限流**，可脚本化无限循环。根因是 `DECOMPOSE.N=50 > DECOMPOSE.R=30`（稀有度倒挂）叠加 `POINTS` 独立发放，两套价值尺度互不通约。

**修复**：以单抽成本为锚，按实测长期占比反解使 `E[总价值] ≈ 45`；合并 `POINTS` 与 `DECOMPOSE` 为单一 `CARD_VALUE` 源并强制单调递增；在 `tests/` 加不变量断言 `E[卡价值] < DRAW_COST` 防回归。

## 四、Medium（56 条，按域）

**前端（11）**
- DrawResultDialog 对 2026-05-20 spec 漏做 6 项（点击翻页 / 淡出 / SSR·UR 光效 / 保底旋转 / img 失败降级 / 卡片宽度）

- 首页「最近抽卡」抽卡后不刷新（effect 依赖是 `user.id`）
- `useAuth.loading` 从未被任何组件消费，首屏必先闪「未登录」
- Toast 计时器在父组件每次重渲染时被重置，可能永不消失
- 两个模态框都缺 `role="dialog"` / 焦点陷阱 / 滚动锁，Esc 行为不一致
- `GachaCard` 的 `<article>`、profile 里程碑 `<div>` 键盘不可达
- 全 app：`aria-label` 0 处、`role=` 0 处、`tabIndex` 0 处、`prefers-reduced-motion` 0 处
- `user-scalable=no` 禁用缩放
- 限定池列表拉了却丢弃：4 个池有 3 个 UI 不可达，并硬编码回退 `genshin`
- localStorage 在渲染期读取，与 SSR 守卫不完整

**API 契约（14）**
- 6 处错误路径不返回 `code`，前端无法按 code 分支
- `apiFetch` 丢弃 status/code 且无条件 `await res.json()`，非 JSON 响应抛未捕获异常
- 无任何 401 自动登出
- `sessionMiddleware` 无 try/catch，D1 抖动会把**含公开端点在内的全部 `/api`** 打成 500

## 五、做得好的地方（建议保留）

1. **原子扣币是全项目最严谨的写法**——`UPDATE ... WHERE id=? AND coins>=?` + `meta.changes` 判定，从根上消除了「先 SELECT 查余额再扣」的 TOCTOU。配合 `schema.sql:10` 的 `CHECK (coins >= 0)` 是双保险。
2. **`draw-engine.js` 被刻意做成无 I/O 纯函数**（61 行、pityConfig 可注入），使概率与保底能被确定性单测。这是本次重构最成功的工程决策。
3. **无结构性安全缺陷**：全仓零 `dangerouslySetInnerHTML`/`eval`；逐条核对 33 个端点，**未发现任何 IDOR**；`env.admin` 缺失时是 fail-closed 而非 fail-open；鉴权走自定义头而非 Cookie，CSRF 结构性不可能。
4. **限流信任边界选对了**——用 `CF-Connecting-IP` 而非客户端可控的 `X-Forwarded-For`。
5. **保底「重置恒胜」语义经实测正确**（node:sqlite 复现），且四个计数器互不污染。
6. **十连退款精确到分**——`drawCost = floor(cost/n)`，n=1..10 全失败时恰好退 900。
7. **防重复扣币的前端防线真实有效**——`if (drawing) return` + `disabled` + z-90 全屏遮罩三重，不是误报。
8. **图片降级链完整**（wsrv 失败降级原图、JSON/302 两种返回形态都处理、fallback 按稀有度分级），且外层 fetch 的 AbortController 用 try/finally 保证 clearTimeout，无定时器泄漏。
9. **AGENTS.md「已知限制」章节诚实**——主动写明 TOCTOU、KV 限流 TOCTOU、localStorage token 的 XSS 风险、占位符 id 部署前必须替换。本次能快速定位问题，很大程度靠这一节。
